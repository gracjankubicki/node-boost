# Astro 5 Compatibility Notes

Use the Astro 5 documentation and the installed adapter's peer range for this project. Keep changes compatible with the repository's exact `astro` and integration versions rather than copying APIs from current examples.

- Verify content collection behavior and loaders against the project's Astro 5 content layer configuration.
- Treat sessions, middleware, Actions, and server islands as runtime capabilities that also depend on the adapter and deployment target.
- Keep route rendering explicit: a static build cannot use request-time cookies or sessions without an on-demand route and a compatible adapter.
- Run the project's Astro checks and a representative adapter smoke test after changes to routing, content, or server code.
