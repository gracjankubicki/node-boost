# Astro 6 Compatibility Notes

Use the Astro 6 documentation and verify integration peer dependencies before upgrading a project. Features introduced after Astro 6 must not be assumed to exist merely because the project has a newer adapter installed elsewhere in a monorepo.

- Keep content loaders and collection schemas explicit and test both build-time and live data paths when both are configured.
- Verify runtime support before combining middleware, sessions, server islands, and route caching; deployment behavior is adapter-specific.
- Treat `client:*` and `server:defer` as separate boundaries with separate fallback, serialization, and caching decisions.
- Run `astro check`, the build, and a request-time smoke test for SSR routes affected by the change.
